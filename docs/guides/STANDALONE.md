# Standalone 独立引擎

桥接器自行管理会话、权限策略、消息队列和模型请求。运行时需要 Node.js、配置好的模型接口，以及已登录 QQ 的 SnowLuma / OneBot 网关。

## 启动与配置

1. 安装标准 Node.js >= 22.13.0 和项目 npm 依赖。`start-ui.bat` 优先检测 Program Files 下的标准 Node；可用 `QQ_BRIDGE_NODE` 指定其他已安装的 Node 可执行文件。
2. 双击 `start-ui.bat`。守护进程启动桥接器并打开需要认证的本地控制台，仅监听本机回环地址。原有 `start.bat` 保持不变。
3. 在概览页的大模型面板中配置 OpenAI 兼容 HTTPS 接口、模型名称和 API Key。
4. 先测试连接，再保存。测试只读取 `GET /models`，不会调用聊天接口或发送 QQ 消息。读取成功但 `modelAvailable=false` 时只表示警告，不能证明所选模型可用。
5. 模型、已保存密钥和系统提示词在下一回合生效。只有运行着守护进程时，控制台重启才会自动拉起桥接；直接运行 `node src/bridge.js` 的进程只会退出。

`ready` 仅表示本地模型配置和凭据有效，不代表 QQ 已连接、AI 未暂停或刚刚联系过模型提供方。QQ 健康状态、AI 暂停状态和最近一次连接测试应分别检查。

## 从控制台启动 SnowLuma

概览页提供仅管理员可使用的 SnowLuma 启动按钮。它使用指定安装目录自带的 `node.exe` 和版本检查器，不使用桥接器的 Node 或相对路径 BAT 命令。已有 QQ 窗口可以保持打开；启动不会关闭 QQ、自动接受协议、绕过 SnowLuma 登录或发送消息。

自动挂载所有已打开 QQ 实例的选项默认关闭。存在多个实例时，请启动网关、打开本地管理页，再挂载目标 QQ 进程。如需全部挂载，应明确勾选并确认；修改选项不会重新配置已经运行的网关。

启动记录、进程句柄、本地端口检查和冷却时间用于防止重复启动。状态不明确或记录过期时会阻止再次启动，不会因此声称网关已连接。手动修复前应确认没有仍在进行的启动操作，不要盲目删除状态。管理链接只表示配置地址通过了本地地址校验，不证明服务正在监听。通过环境变量修改端口并在外部启动的实例不属于本启动器的记录范围，请另行检查。进程已启动、OneBot WebSocket 已认证连接、模型配置就绪是三个不同状态。

模型 API Key 来自所选模型提供方，不来自 QQ 或 SnowLuma。请保密，并确认额度和模型访问权限。

## 配置与密钥

```json
{
  "engine": {
    "backend": "standalone",
    "directLLM": {
      "provider": "openai-compatible",
      "baseUrl": "https://your-provider.example/v1",
      "model": "your-model",
      "apiKeyEnv": "QQ_DIRECT_API_KEY",
      "requestTimeoutMs": 90000,
      "turnTimeoutMs": 900000,
      "maxRounds": 16,
      "maxRetries": 2,
      "vision": true,
      "webSearch": true
    }
  }
}
```

模型设置位于 `engine.directLLM`。`engine.backend` 可省略，填写时使用 `standalone`；如果设置了 `QQ_BRIDGE_ENGINE` 环境变量，也应使用该值。

密钥不会在状态接口返回，不会预填到表单、写进日志或保存在浏览器存储中。密码框留空会保留已保存密钥；清除必须明确勾选相应选项。已保存密钥位于受本地访问控制限制的 `state/direct-engine-secret.json`，并绑定提供方和接口地址。这不是加密，当前系统账号和管理员仍可读取。环境变量密钥优先于已保存密钥；清除文件中的密钥不会清除环境变量。切换提供方或地址不会复用作用域不匹配的旧密钥。

需要 DeepSeek 搜索时，单独设置 `webSearch.apiKeyEnv` 指定的环境变量；未配置时 `auto` 可回退 Bing。搜索内容会发送到实际使用的服务。

## 更新与备份

1. 记录 AI 当前是否暂停。维护期间需要停止回复时，可先在控制台暂停 AI，再停止桥接及其守护进程。
2. 备份 `config.json`、`roles/`、`prompts/`、`state/` 和自备的 `audio/` 素材，不要把备份上传到 GitHub。
3. 更新公开源码和依赖，保留私人配置、秘密文件、人格、记忆与语音设置；不要用示例文件覆盖它们。
4. 启动桥接，分别确认模型配置、网关连接和 QQ 账号状态。配置完整时无需重新输入 Key。
5. 将 AI 暂停状态恢复为维护前的状态，并重新读取确认。**暂停会跨重启保存；桥接在线不代表 AI 正在处理消息。**

## 会话与行为边界

- 会话使用 `state/sessions-standalone.json` 中的本地 UUID，由桥接器管理映射。
- 启动时轮换 QQ 工具令牌，撤销所有旧工具令牌，不改变聊天记录。
- 模型仅能调用会话授权的安全工具，不能执行命令或读写任意本地文件。
- 模型普通文本保持私有。发送必须经过绑定宿主会话凭据和目标 ID 的安全 QQ 工具，同时满足白名单和逐工具开关；静默管理回合不能发送 QQ 消息。
- 每个回合使用消息快照、近期 QQ 历史、人格卡、逐会话背景和本地记忆重建上下文。修改人格或背景在下一回合生效。
- 缺少模型凭据时会合并待唤醒任务，而不是丢弃未读消息；保存有效设置后会重放队列。模型请求有界超时和重试，发送工具不会自动重放。
- 仍然执行游标授权、明确的 `throughSeq`、睡眠前观察、暂停、重置和白名单撤销。有限睡眠到期后的失败会退避，避免立即反复运行。
- 系统提示词位于 `prompts/standalone-system.txt`。提示词编辑器只修改该本地文件并保存本地备份。
- 黑话词库支持人工管理，以及模型通过安全工具查询和提交候选；管理员确认后可注入后续对话。

## 离线验证

使用符合要求的 Node，不要误用 PATH 中的旧版本：

```text
npm run test:standalone
npm run test:engine-settings
npm run test:engine-ui
npm run test:direct
```

测试使用虚构密钥、临时配置和状态、模拟 OneBot 网关及模型响应，验证本地会话创建和重置、安全工具、私有回合、控制台设置和提示词保存。测试不连接真实 QQ 或模型服务。
